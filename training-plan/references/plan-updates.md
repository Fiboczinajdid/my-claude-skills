# Updating an existing plan

Read this file when the person comes back with a plan and wants to change it: they've stalled, the weights don't fit, a block has ended, they feel run down, or their circumstances have changed.

An update goes through **the same process as building a plan**: data → research → "research → decision" note → checklist → plan. There's one difference: change only what you consider necessary. Leave the parts of the plan that work as they are. That gives the person continuity, makes results easier to compare, and keeps the changes clear.

## 1. Collect data

- **The current plan.** If it isn't in the conversation, ask them to paste or describe it (a photo works).
- **Explanation level** (none / short / detailed), if you don't know what they chose before.
- **What happened:** how long they've been on the plan; weight × reps in key exercises, ideally from the first and the last week; results in tests tied to the goal (e.g. vertical jump, 5 km time); which exercises went well and which badly; how many sessions they actually did.
- **How they feel:** fatigue, sleep, pain, new injuries.
- **What changed:** time, equipment, schedule, goal, other activities, race date.

Same rules as in the interview: batches of 3–5 questions, don't ask again about what's already been said, any question can be skipped, skipped = "no data" with no made-up values. If a skipped item is key to a decision, ask once at the end whether they're sure they want to skip it. For a new goal or a new motor quality, use `data-by-goal.md`.

## 2. Recognize the signals

| Signal | What to consider |
|---|---|
| Weights from the ranges clearly too light (they do more reps than the top of the range in every set) | Increasing the weight by the smallest sensible increment for that exercise; recalculate the ranges from their actual results |
| Weights clearly too heavy (they don't reach the bottom of the rep range, or technique breaks down) | Reducing the weight; check whether fatigue is the cause (then see below) |
| No progress in a key exercise for 2–3 weeks | Changing the rep range, the exercise variant or the volume; first rule out fatigue and poor recovery |
| End of a block (planned period) | Moving to the next phase, e.g. from building volume to higher intensity, or a new block for the next stage of the goal |
| Clear fatigue, worse sleep, dropping results, worse jump or sprint quality | A lighter week or lower volume; only then further progression |
| Pain or a new injury | Swapping exercises that load that area; for a serious condition, apply the safety rule from SKILL.md |
| Changed circumstances (less time, different equipment, new schedule) | Rebuilding the weekly split or exercise selection while keeping the goal's priorities |
| Changed goal or priorities | Reinterpreting the goal (motor qualities, main and secondary goals, conflicts) and confirming with the person |
| The person skips some sessions | A plan fitted to their real availability instead of an ideal one that isn't being done |

The table is a starting point for thinking, not a ready decision. Choose the specific solution based on research and this person's situation.

## 3. Research and decision

- For each variable you're considering changing, search for research the same way as when building the plan: in English, with the source hierarchy (meta-analyses and systematic reviews → ACSM and NSCA position stands → single studies → blogs only with a note), accounting for this person's population.
- Fit the scope of the search to the changes: adjusting a weight from actual results usually needs no new research, while changing the phase, the volume or how goals are combined does.
- Write the "research → decision" note for the variables you're changing. Include what research can't provide: how this person actually responded to the plan so far.
- If you decide nothing needs to change, say so plainly and explain why. Change for its own sake isn't optimal.
- Go through the checklist from SKILL.md for the updated plan.

## 4. Show the changes

1. **What changes and why:** a short list of changes, to the extent of the chosen explanation level. For "none", the list of changes alone is enough.
2. **The full updated plan**, in the same format as in SKILL.md, with changed items marked (e.g. "(changed)" in the "Notes" column). The person then has one current version instead of two to piece together.
3. **When to change the plan**, for the new version.
4. **Sources**, if you used new ones for this update.
